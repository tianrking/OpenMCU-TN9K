# Tang Nano 9K 资源与外设扩展路线图

> 适用基线：OpenMCU-TN9K RISC-V 产品模式、硬件 ABI `0.5`、
> `omcu_tn9k_mcu_top`。
> 本路线图把“芯片资源理论余量”“开发板实际可接引脚”“已通过 P&R”与“真板可交付”
> 严格分开。它不是对未来外设的完成承诺。

## 1. 当前资源结论

最近一次产品模式布局布线记录见[验证与发布状态](validation-and-release.md)。目标为
`GW1NR-LV9QN88PC6/I5` / `GW1N-9C`，27 MHz 时钟约束下的记录如下：

| 资源 | 已用 / 总量 | 理论剩余 | 扩展决策 |
| --- | ---: | ---: | --- |
| LUT4 | 6,594 / 8,640（76.32%） | 2,046（23.68%） | 可以增加小到中等的纯逻辑外设，但不能把全部余量当作可用预算。 |
| DFF | 1,758 / 6,480（27.13%） | 4,722（72.87%） | 寄存器不是当前主要约束。 |
| BSRAM | 26 / 26（100%） | **0** | 禁止把新功能建立在大 FIFO、缓存或新增片上 RAM 上。 |
| IOB | 15 / 276（5.43%） | 芯片层面 261 | 不等于开发板有 261 根可安全使用的外部针脚；见第 3 节。 |
| 时序 | 27 MHz 约束；40.190 MHz 实现结果 | 12.155 ns 记录余量 | 每次 RTL 扩展都必须重新报告，历史余量不能继承。 |

### 1.1 规划预算，而不是“塞满 LUT”

布局布线、扇出、I/O 约束和未来修复都会改变 LUT 映射。为了让产品平台保持可维护，采用
以下门槛：

| 门槛 | 最大 LUT 使用 | 可供本次路线图新增的近似 LUT 预算 | 用途 |
| --- | ---: | ---: | --- |
| 推荐目标：保留至少 15% | 7,344 | 约 750 | v0.6 的低风险外设和平台可观测性。 |
| 条件上限：保留至少 10% | 7,776 | 约 1,180 | 只有 P&R、时序和真板均通过时才可使用。 |
| 禁止目标 | 大于 7,776 | 不接受 | 不以牺牲后续修复、时序和可维护性来换功能数量。 |

上述是规划带宽，不是综合工具承诺的精确单元数。每个候选项先独立综合，再根据实际 LUT、
DFF、时序和 I/O Bank 报告决定是否进入产品版。

### 1.2 BSRAM 已满意味着什么

当前 8 KiB Boot ROM 加 44 KiB SRAM 是 ABI 0.5 产品模式的固定内存几何；其中应用可用
40 KiB，Bootloader 保留 4 KiB。它已经使用所有 26 块 BSRAM。

- 可以接受：寄存器、状态机、计数器、小型移位寄存器和经明确审查的少量 LUT RAM；
- 不可以直接接受：大 TX/RX FIFO、逻辑分析仪采样缓存、帧缓冲、缓存型 QSPI XIP、
  高吞吐 DMA 缓冲或新的大块片上程序 RAM；
- 需要新存储策略：先验证板载 PSRAM 或外部串行存储，且不能改变已经发布的 A/B User
  Flash 升级语义。

## 2. 候选能力评估

资源级别是实施前估计，不是已完成的 P&R 结果。`低`表示应主要消耗少量 LUT/DFF；`中`和
`高`必须以独立产品顶层 P&R 为准。

| 候选能力 | 预计逻辑/存储影响 | I/O 与外部条件 | 产品价值 | 决策 |
| --- | --- | --- | --- | --- |
| 现有 SPI/I2C 的 ADC、DAC、RTC、EEPROM、传感器 SDK 驱动 | 无新 FPGA RTL | 使用已有 SPI0/I2C0 与模块 | 高；立即扩展可用场景 | **P0：优先**。不增加 LUT，但须先完成现有总线 HIL。 |
| W5500 等外置 SPI 以太网控制器驱动 | 无新 FPGA RTL，最多一根 GPIO IRQ | SPI0 与 TF 卡共享，需外置 3.3 V 模块 | 高；避免在 FPGA 中实现以太网 MAC/PHY | **P0：推荐**。它不是片上以太网 MAC。 |
| GPIO 扩展档案（先从公开 3 路扩到 8–12 路） | 低；主要为顶层、OE 和中断位宽 | 仅使用经过原理图、电压与 HIL 确认的扩展针脚 | 高；最通用 | **P1：推荐**。不承诺把所有未用 IOB 暴露为 GPIO。 |
| UART1（无大 FIFO、RX/TX + IRQ） | 低到中 | 两个确认的同电压扩展 I/O | 高；UART0 保留给 Bootloader/日志 | **P1：推荐**。先做无 FIFO 基线，避免 BSRAM 需求。 |
| PWM1（4 路共享计数器） | 低 | 3–4 个确认的输出 I/O | 高；电机、灯带、舵机 | **P1：推荐**。不在首版承诺互补、死区或高压栅极驱动。 |
| TIMER1 / 输入捕获 / 正交编码器 | 低到中 | 2–4 个输入 I/O，必须做同步与去抖策略 | 高；机器人和工业输入 | **P1：推荐**。禁止把异步高速信号直接当普通 GPIO 使用。 |
| 复位原因、软件回到 Bootloader 请求、运行计数与诊断寄存器 | 低 | 无额外 I/O | 高；提高开发和故障诊断体验 | **P1：推荐**。需同时更新 Bootloader、SDK、ABI 特性位和回归。 |
| SPI1 到板载 32 Mbit SPI Flash，先做数据存储 | 低到中 | 固定板载 Flash 引脚；不能与配置/下载路径冲突 | 高；日志和只读资源 | **P2：先做可行性/HIL**。先做数据读写，不承诺 XIP 或文件系统。 |
| 板载 64 Mbit PSRAM 控制器 | 中到高，且有时序风险 | 固定板载 PSRAM 引脚、专用时序与板级测试 | 高；解决 BSRAM 已满 | **P2：可行性分支**。先做内存测试与 P&R，再决定是否进入产品 ABI。 |
| Classic CAN 2.0B 控制器（无大 FIFO） | 中到高 | 两根 I/O 加外置 CAN 收发器；需要总线/错误帧 HIL | 中到高 | **P3：二选一研究项**。不可与 PSRAM 大改在未测量资源前同时承诺。 |
| DMA | 中到高，通常需要 FIFO/仲裁缓冲 | 需要明确存储架构 | 中 | **P3：依赖 PSRAM/内存架构结论**。当前不在产品基线实现。 |
| QSPI XIP、缓存、片上逻辑分析仪 | 高，通常需要 BSRAM | 存储与缓存策略 | 中 | **不进入当前基线**。先解决 BSRAM 为零的问题。 |
| USB FS、HDMI、RGB 帧缓冲、FPGA 内以太网 MAC/PHY | 高、时钟/物理层复杂、常需缓存 | 板载连接器、PLL、高速电气和大量验证 | 场景专用 | **不作为 TN9K MCU 基线目标**。需要独立产品分支或更大 FPGA。 |
| ADC、DAC、比较器、温度传感器 | FPGA 没有对应模拟硬件 | 必须使用外置模拟器件 | 高但不是数字 RTL 任务 | **外置器件 + 现有 SPI/I2C 驱动优先**。 |

## 3. I/O 不是“261 根通用针脚”

Tang Nano 9K 芯片有 276 个 IOB，当前设计使用 15 个；但是开发板连接器、I/O Bank 电压、
复用外设和专用功能决定了实际可用范围。Sipeed 官方资料说明该板有两个 24P 扩展排针、
TF、SPI/RGB/HDMI 显示接口、32 Mbit SPI Flash 和 64 Mbit PSRAM；完整连接关系应以官方
[板卡资料](https://wiki.sipeed.com/hardware/en/tang/Tang-Nano-9K/Nano-9K)和
[原理图](https://dl.sipeed.com/fileList/TANG/Nano%209K/2_Schematic/Tang_Nano_9k_3672_Schematic.pdf)
及手中板卡 revision 为准。

### 3.1 已承诺且必须保留的引脚组

| 资源 | 当前 pin / 约束 | 规则 |
| --- | --- | --- |
| 时钟、复位 | 52、4 | 27 MHz 时钟和复位是救砖路径，不为可选外设复用。 |
| UART0 | 17 / 18 | Bootloader 升级与恢复入口，必须保留 TX、RX、GND 与复位流程。 |
| SPI0 | 38 / 37 / 36 / 39 | 与 TF 卡共享；可接一个外置 SPI 目标，但不能与 TF 并行使用。 |
| I2C0 / PWM0 / GPIO0[6:8] | 25–30 | 当前已公开的 3.3 V 扩展组；优先在这里完成最小 HIL。 |
| LED | 10、11、13–16 | 板载状态指示，不作为外部 GPIO 承诺。 |

### 3.2 可研究、但尚未分配的 I/O

- J5 上还存在 RGB 相关信号组；它们与显示接口复用，只有在确认 Bank 电压、连接器占用、
  终端和对应板卡 revision 后，才可作为“扩展 GPIO 档案”的候选。
- J6 含有显示/低电压相关信号，**不能**默认按 3.3 V 通用 GPIO 对外公布。
- 板载 SPI Flash、PSRAM、LCD/RGB/HDMI 连接器都不是“空 IOB”；要增加控制器必须建立
  独立 CST、时序约束、物理连接规则和 HIL 矩阵。
- 片上 USB-JTAG/UART 调试通道和配置相关引脚不应被软件外设随意复用。

任何新增 pin 必须同时提交：顶层端口、CST、板级电压说明、SDK 逻辑名、仿真测试、
P&R 报告与实板记录；不能只在文档中把 package pin 宣称为可用。

## 4. 推荐实施顺序

### P0：先让现有 MCU 真正可交付（不消耗新增 LUT）

1. 完成 Tang Nano 9K 真板 HIL：SRAM 下载、配置固化、冷启动、UART Bootloader、User
   Flash A/B、断电回退、SPI/I2C/PWM/GPIO/WDT/IRQ 波形；
2. 为现有 SPI0/I2C0 发布外置器件示例：传感器、RTC、ADC/DAC、EEPROM，以及 W5500
   等外置网络控制器；
3. 建立板卡 revision 与实际可焊接/可用排针清单，明确哪些是 3.3 V、1.8 V、显示复用或
   禁止复用；
4. 用通过 HIL 的 `.fs`、manifest、P&R 报告、示例 `.omcu` 和 SHA-256 创建正式 Release。

### P1：v0.6 低风险数字扩展（目标新增不超过约 700 LUT）

1. 增加受控 GPIO 扩展档案，不破坏 UART0、复位、SPI0/TF 的既有契约；
2. 新增 UART1 无 FIFO 基线；
3. 新增共享计数器的 4 路 PWM 与一个输入捕获/编码器计时器；
4. 增加复位原因、软件请求 Bootloader、运行/故障诊断寄存器；
5. 逐项增加 MMIO 基址、`SYSCTRL.FEATURES` 位、生成的 SDK 头、例程、RTL 与编译后
   固件测试；
6. 必须保持 LUT 使用不高于 7,344、BSRAM 26/26 不变，并重新完成 P&R 与 HIL。

### P2：存储与带宽可行性（不直接承诺产品 ABI）

1. 调查板载 32 Mbit SPI Flash 的独立数据访问，先交付只读/日志数据通道；
2. 建立低频 PSRAM 读写测试器、地址/数据压力测试、时序报告与真板温度测试；
3. 决定是否以外部 PSRAM 替代未来的 FIFO/缓存需求；
4. 若 P2 后 LUT 仍低于 7,776、时序和 HIL 全部通过，才评估是否将其升级为可公开 SDK
   能力。

### P3：只选择一个高风险方向

在 P2 测量完成前，以下两条路线只能选一条进入实现：

- **工业接口方向**：Classic CAN 2.0B + 外置收发器 + 严格错误处理/HIL；
- **存储/性能方向**：PSRAM 支撑下的 DMA、较小 FIFO、显示或高吞吐协议。

USB、HDMI、RGB 帧缓冲、完整以太网 MAC/PHY 和大缓存逻辑不进入当前 9K MCU 主线；若它们
成为刚性需求，应优先评估 Tang Nano 20K 或具有更多 SRAM/高速 I/O 的板卡，而不是压垮
当前产品的余量。

## 5. 每项功能的不可省略门槛

一个候选外设只有同时满足下面所有条件，才可从“路线图”转为“已支持”：

1. 明确硬件功能与 ABI 版本，不破坏 ABI 0.5 已发布寄存器；
2. 具备独立 RTL 单元测试、系统测试、SDK API、至少一个编译后固件例程；
3. `SYSCTRL.FEATURES`、规格 JSON、自动生成头文件、中文数据手册与烧录/恢复说明同步更新；
4. 对精确 `GW1NR-LV9QN88PC6/I5` 完成综合、P&R、packing，并记录资源、时序、警告和
   位流哈希；
5. 在实体板做电压、电平、复位、异常、掉电和目标外设 HIL；
6. 通过后才向第三方宣称“可用”，并将相应工件附到 GitHub Release。

## 6. 结论

当前剩余 2,046 LUT 是继续完善 MCU 平台的空间，不是客户应用代码的空间，也不是要求把
资源耗尽的理由。最合理的下一版是“**先 HIL，再以 GPIO 扩展、UART1、PWM 多通道、
输入捕获和诊断能力形成约 700 LUT 的 v0.6 小步升级**”；存储扩展和 CAN/DMA 需要先以
独立 P&R 与真板实验决定是否值得进入主线。
